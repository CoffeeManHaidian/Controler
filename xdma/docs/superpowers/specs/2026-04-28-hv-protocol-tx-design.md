# 高压协议发送封装设计说明

## 目标

在当前已经稳定的 `SRIO Base` 基线上，新增一个独立的高压协议发送封装层，用于把 `16bit` 数据封装成 `32bit` 协议字：

- 高 16 位：地址 `addr[15:0]`
- 低 16 位：数据 `data[15:0]`

第一阶段只实现发送侧，不改变当前 `SFP3 / AD9516 / GT / ILA / 回环` 基础结构，也不立即替换现有 RX 校验语义。

## 背景

当前 `SRIO Base` 已经验证：

- `SFP3` 通道可正常工作
- `AD9516` 时钟初始化链稳定
- `TX/RX` ILA 可正常观测
- `RX` 侧已能收到与 `TX` 等价的循环序列

因此，高压协议的最佳插入位置不是底层收发壳，而是当前发送测试层。现有发送入口位于：

- `D:\Controler\xdma\gtwizard_0_ex\gtwizard_0_ex.srcs\sources_1\imports\example_design\gtwizard_0_gt_frame_gen.v`

## 设计原则

### 1. 协议层与传输层分离

高压协议封装层只负责：

- 接收 `16bit` 数据
- 自动生成递增地址
- 输出 `32bit` 协议字

它不负责：

- GTX/SRIO 时钟与复位
- 光模块初始化
- 底层链路调试

### 2. 为未来外部程序接入保留稳定接口

第一阶段即定义外部数据输入接口，避免后续把“默认测试源方案”重写成“外部程序输入方案”。

### 3. 第一阶段优先可验证

即使外部程序暂未接入，也必须能上板验证。因此模块内部需要保留默认测试源。

## 模块方案

新增模块：

- `D:\Controler\xdma\project_1\project_1.srcs\sources_1\new\hv_proto_tx.v`

该模块作为发送封装层，位于当前 `SRIO Base` 发送数据源与 `frame_gen` 之间，或直接替换当前固定 ROM 读表发送逻辑。

## 接口定义

### 输入

- `clk`
  - 发送数据域时钟，第一阶段使用当前发送链一致的用户时钟域
- `rst`
  - 同步复位
- `data_in[15:0]`
  - 外部程序输入的数据
- `data_valid`
  - 外部数据有效指示
- `use_internal_source`
  - 测试模式选择
  - `1`：使用内部默认测试源
  - `0`：优先等待外部数据输入
- `addr_base[15:0]`
  - 地址起始值
- `addr_limit[15:0]`
  - 地址上限值

### 输出

- `packet_out[31:0]`
  - 输出高压协议字
  - 格式：`{current_addr, current_data}`
- `packet_valid`
  - 输出协议字有效
- `current_addr[15:0]`
  - 当前地址，供 ILA 观测
- `using_internal_source`
  - 当前是否处于内部测试源模式，供调试使用

## 行为定义

### 地址生成规则

- 初始地址为 `addr_base`
- 每成功发送一个协议字，地址加 `1`
- 当地址达到 `addr_limit` 后：
  - 下一拍地址回到 `addr_base`
  - 继续循环发送

这是第一阶段选定的行为，即“地址到上限后回卷重发”。

### 数据来源规则

#### 模式 A：内部默认测试源

当 `use_internal_source = 1` 时：

- 忽略 `data_in/data_valid`
- 使用模块内置默认测试序列
- 默认测试序列采用有限长度循环表，例如 16 个 `16bit` 样本
- 每次成功发送一个协议字，测试序列索引加 `1`
- 索引到末尾后回到首项

#### 模式 B：外部数据输入

当 `use_internal_source = 0` 时：

- 仅当 `data_valid = 1` 时发送新协议字
- 使用 `data_in` 作为当前数据字段
- 每输出一个有效协议字，地址递增一次

### 输出字格式

高压协议第一阶段输出固定采用：

```text
packet_out[31:16] = current_addr[15:0]
packet_out[15:0]  = current_data[15:0]
```

## 默认测试源

第一阶段内部默认测试源只服务于上板验证，不承载业务语义。

建议使用 16 项 `16bit` 测试表，便于在 ILA 中快速识别循环。例如：

- `16'h1000`
- `16'h1001`
- `16'h1002`
- `16'h1003`
- `16'h1010`
- `16'h1011`
- `16'h1012`
- `16'h1013`
- `16'h1020`
- `16'h1021`
- `16'h1022`
- `16'h1023`
- `16'h1030`
- `16'h1031`
- `16'h1032`
- `16'h1033`

这样 ILA 中可以同时观察到：

- 地址递增
- 数据模式递增
- 整体 32bit 输出是否形成可解释循环

## 集成方式

第一阶段推荐做法：

1. 保留当前 `SRIO Base` 的顶层、时钟壳、ILA、远端构建流
2. 新增 `hv_proto_tx.v`
3. 在发送链中，用 `hv_proto_tx` 的 `packet_out[31:0]` 替换当前测试数据源中的有效载荷部分
4. 保留必要的控制字符生成机制，确保不破坏现有 `SRIO Base` 发送链协议结构

换句话说，第一阶段不是重写整条发送链，而是替换其中“业务有效载荷来源”。

## 调试策略

### TX 侧建议新增或保留观测点

- `packet_out[31:0]`
- `current_addr[15:0]`
- `using_internal_source`
- `tx_read_counter` 或同类发送步进计数
- `gt0_txdata[31:0]`

### 第一阶段重点验证内容

1. 地址是否从 `addr_base` 开始递增
2. 地址是否在达到 `addr_limit` 后回卷
3. 内部默认测试源是否按预期循环
4. 加入封装层后，当前 `SRIO Base` 是否仍能稳定发送与回环

## 第一阶段不做的内容

为了保持范围清晰，以下内容不纳入本阶段：

- 高压协议 RX 解析器
- 高压协议专用 checker
- 超范围后的无效字填充策略
- 控制频率 `1000Hz` 的系统级节拍调度
- 单次最多 420 个控制字的批处理规则
- 主机程序到 FPGA 的正式在线输入链路

这些内容留到后续阶段，在当前发送封装稳定后逐步引入。

## 验收标准

第一阶段完成后，应满足：

1. `TX ILA` 中能直接看到 `{addr,data}` 组合输出
2. 地址按预期递增，并在上限后回卷
3. 默认测试源序列在 ILA 中清晰可识别
4. 不破坏当前 `SRIO Base` 的链路稳定性
5. 远端测试机上仍可正常生成并烧写 `bit + ltx`
